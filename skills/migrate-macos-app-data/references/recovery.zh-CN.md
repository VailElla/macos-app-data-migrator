# 非破坏性恢复与中断处理

迁移日志位于外接目标旁边：

```text
.<目标名称>.migrate-macos-app-data.json
```

日志记录准确源/目标、源树启动快照、进度、硬链接映射与 SHA-256，不包含文件正文、密码或凭据。

## 复制中断

- 源程序/数据没有被迁移脚本删除或重命名，仍是完整的首要恢复点。
- 重新连接同一个外接宗卷，确认挂载路径与宗卷 UUID 未改变，再重复完全相同的 `copy ... --execute` 命令。
- 已完成的目标文件会重新哈希；相同文件跳过，不同文件拒绝覆盖。本工具只会重写由自己迁移 ID 标记、且位于外接目标内部的临时副本。
- 不要在挂载点消失时创建同名目录，不要删除迁移日志“重新开始”。

## 校验失败

- 立即停止，不删除源或外接副本。
- 确认程序与辅助进程完全退出，检查源是否变化、外接盘健康与连接稳定性。
- SHA-256、元数据、ACL、扩展属性或签名任一失败，都不能进入访达清理门槛。
- 如用户最后决定放弃外接副本，只能由用户在访达中处理外接生成物；不要用终端代删内置源。

## 已在访达改名，但尚未建立链接

如果决定取消，用户直接在访达中把 `Name.internal-backup` 改回原名。没有源数据需要从外接盘复制回来。

## 已建立软链接，但程序测试失败

1. 完全退出程序和辅助进程。
2. 在访达中定位原路径；用户把软链接移到废纸篓。
3. 用户把同级的 `Name.internal-backup` 改回原名。
4. 从内置源启动，确认恢复正常。
5. 保留外接副本和日志，直到原因查明；沙盒拒绝通常意味着普通软链接不够。

整个回滚不需要管理员密码或终端删除命令。

## 内置 `.app` 尚在时外接程序失败

直接改回启动内置 `.app`。不移动、不删除内置程序。用户如果放弃外接副本，可在访达中处理外接 `.app`。

## 备份已移到废纸篓

- 尚未清倒废纸篓：用户用访达“放回原处”，然后按上面的软链接回滚步骤操作。
- 已清倒废纸篓：不要删除外接唯一副本。恢复到内置盘需要足够最终容量和一个单独审查的复制流程；本技能不会假装能够在空间不足时无损恢复。

## 外接盘断开

立即退出程序。重新连接原宗卷，确认相同挂载路径和 UUID 后再继续。不要让程序在断盘期间写入原软链接位置，以免生成新的内置大型目录。
