# 访达手动交接与释放内置空间

## 强制规则

- 在删除/改名交接阶段，迁移工具只运行 `open -R`，在访达中选中准确路径；它不会用终端命令代替用户的访达操作。
- 数据目录默认在用户明确授权后由 Codex 通过访达移到废纸篓但不清空，并复核源路径已腾出；永久删除仍是独立确认门槛。用户明确偏好同级备份时才使用可回滚改名。
- 不索取管理员密码，不运行 `sudo`，不用 `rm`、`mv`、`ditto --delete` 或其他终端命令删除、覆盖、替换内置程序/数据。
- “确认路径”和“确认删除”是两个不同确认。只有完整校验与程序实测都通过后，才请求后者。

## 程序 `.app`

1. 保留内置 `.app`，从外接盘启动已校验副本。
2. 完成登录、读取、写入、退出、重启与更新器检查。
3. 运行 `reveal`，让访达选中内置 `.app`。
4. 再次口头显示源路径和目标路径，并说明外接盘断开时程序不可用。
5. 用户明确确认后，由用户在访达中选择“移到废纸篓”。
6. 不为 `.app` 建立原路径软链接。

## 数据目录

1. 完整校验通过后运行 `reveal`，让访达选中原数据目录。
2. 用户明确授权后，由 Codex 通过访达把原目录移到废纸篓但不清空；不得改用终端命令。用户明确偏好同级备份时，才在访达中改名为 `Name.internal-backup`。
3. 确认原路径已空出、废纸篓源仍可“放回原处”（或同级备份仍存在），再运行 `link` 的预演。
4. 用户审核准确路径后才执行 `link --execute`。此命令只建立软链接。
5. 保留废纸篓中的恢复副本（或同级备份），完成真实读取、写入、完全退出、重启和更新检查。
6. 检查新写入确实落在外接盘，而不是在内置盘重新生成大型目录。
7. 用户确认成功后，说明废纸篓中的内置源可以永久删除；清空废纸篓必须在动作发生时再次确认，且不能连带处理未获授权的其他内容。
8. 若使用同级备份，运行 `reveal --path "/exact/Name.internal-backup"` 后再移到废纸篓。

迁移不是备份。永久删除废纸篓中的内置恢复副本后，外接盘成为唯一工作副本，硬盘日后物理损坏不属于迁移完整性保证；重要数据需要独立备份。

## 确认用语

默认废纸篓流程应清楚说明：

> 外接副本 `[准确目标路径]` 已完成全量校验，程序也已完成读取、写入、退出和重启测试。内置原源 `[准确源路径]` 已在废纸篓中，当前仍可“放回原处”。永久删除这个准确项目后将失去这项回滚；若选择“清空废纸篓”，还会同时永久删除其中所有其他项目。请确认是否要由你在访达中执行永久删除。

用户明确选择同级备份时，应清楚说明：

> 外接副本 `[准确目标路径]` 已完成全量校验，程序也已完成读取、写入、退出和重启测试。现在访达选中的是同级备份 `[准确备份路径]`。把它移到废纸篓后，只在这个准确项目尚未永久删除时保留回滚。请确认是否要由你在访达中把该备份移到废纸篓。

没有与实际交接状态相匹配的明确确认，就保留恢复副本并结束本轮。绝不自动清空无关的废纸篓内容。
