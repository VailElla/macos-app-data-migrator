# 访达手动交接与释放内置空间

## 强制规则

- 在删除/改名交接阶段，迁移工具只运行 `open -R`，在访达中选中准确路径；它不会用终端命令代替用户的访达操作。
- 用户亲自在访达中重命名或“移到废纸篓”。
- 不索取管理员密码，不运行 `sudo`，不用 `rm`、`mv`、`ditto --delete` 或其他终端命令删除、覆盖、替换内置程序/数据。
- “确认路径”和“确认删除”是两个不同确认。只有完整校验与程序实测都通过后，才请求后者。

## 程序 `.app`

1. 保留内置 `.app`，从外接盘启动已校验副本。
2. 完成登录、读取、写入、退出、重启与更新器检查。
3. 运行 `reveal`，让访达选中内置 `.app`。
4. 再次口头显示源路径和目标路径，并说明外接盘断开时程序不可用。
5. 用户明确确认后，由用户在访达中选择“移到废纸篓”。
6. 不为 `.app` 建立原路径软链接。

## 数据目录

1. 完整校验通过后运行 `reveal`，让访达选中原数据目录。
2. 用户在访达中重命名为 `Name.internal-backup`。这是同卷改名，不复制数据。
3. 确认原路径已空出、备份仍存在，再运行 `link` 的预演。
4. 用户审核准确路径后才执行 `link --execute`。此命令只建立软链接。
5. 保留备份，完成真实读取、写入、完全退出、重启和更新检查。
6. 检查新写入确实落在外接盘，而不是在内置盘重新生成大型目录。
7. 用户确认成功后，运行 `reveal --path "/exact/Name.internal-backup"`。
8. 用户在访达中把备份移到废纸篓；提醒只有清倒废纸篓后空间才真正释放。是否清倒仍由用户决定。

迁移不是备份。清倒后外接盘成为唯一工作副本，硬盘日后物理损坏不属于迁移完整性保证；重要数据需要独立备份。

## 确认用语

在最终释放空间前，清楚说明：

> 外接副本已完成全量校验，程序也已完成读取、写入、退出和重启测试。现在访达选中的是内置备份 `[准确路径]`，外接目标是 `[准确路径]`。把它移到废纸篓后，回滚将依赖外接副本。请确认是否由你在访达中执行。

没有这项明确确认，就保留备份并结束本轮。
