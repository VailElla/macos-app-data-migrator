# macOS 程序与数据迁移兼容性

## 先证明程序如何找到新位置

迁移“字节”与迁移“可正常运行的程序”是两个独立问题。完整哈希可以证明副本一致，但只有程序的真实启用、读写、退出和重启测试才能证明兼容。

| 组件 | 首选接入方式 | 何时可用 | 必须验证的风险 |
|---|---|---|---|
| `.app` 程序包 | 直接从外接 APFS 启动 | 独立应用允许从可移动宗卷运行 | 签名、Gatekeeper、登录项、更新器是否接受新路径 |
| 大型数据目录 | 程序原生位置设置 | 程序提供库、模型、下载或游戏内容位置 | 设置是否覆盖所有大型数据、重启后是否保持 |
| 非沙盒数据 | 原路径软链接 | 程序及其更新器允许解析外接目标 | 更新是否替换软链接、断盘时是否误建空目录 |
| 沙盒数据 | 文件夹选择器或安全作用域适配器 | 已针对该程序实测 | 普通软链接即使在访达可用，沙盒仍可能拒绝目标 |

运行：

```bash
python3 scripts/inspect_app.py "/absolute/path/App.app" --verify-signature
```

看到 `Sandboxed: yes` 时，把普通软链接视为未证明方案。优先查程序设置；没有原生方式或已验证适配器时，保留源数据并停止。

## 精确划定组件

- 一次只迁移一个 `.app` 或一个目录。程序与数据都迁移时分别复制、分别校验、分别实测。
- 只选择占空间的大型、可重新定位内容，例如游戏资源、媒体库、下载、离线模型或用户明确要求保留的缓存。
- 偏好设置、登录状态、存档、数据库、锁文件、钥匙串引用和自动更新状态通常留在内置盘，除非程序明确支持迁移。
- 不迁移整个 `~/Library`、整个 `~/Library/Containers`、整个程序容器、整个 `Application Support` 或同步服务根目录。
- iCloud Drive、Dropbox、OneDrive、Time Machine 和其他同步根目录必须先按服务规则暂停并单独审查。

## 接近零可用空间时的空间模型

- 源目录全程保持原位；不会在内置盘生成迁移副本、压缩包、磁盘镜像、日志或逐文件临时副本。
- 目标外接盘需要容纳完整最终副本，并保留约 64 MiB 工具余量。
- 迁移日志和临时文件与目标相邻，所以中断不会回写大型内容到内置盘。
- 数据接入需要原路径软链接时，会在内置盘写入一个很小的链接元数据。若连这点元数据也无法写入，应先在访达中释放少量空间或使用程序原生设置。
- macOS 自己可能产生少量日志、TCC 权限或安全书签元数据；这不属于迁移负载，也无法保证绝对为零。

## 文件系统与生命周期

- 只接受能被 `diskutil` 明确识别为外接的 APFS 宗卷；生产 CLI 不提供内部宗卷绕过参数。
- exFAT、NTFS、网络文件系统和云盘可能丢失 ACL、扩展属性、resource fork、硬链接、权限或大小写语义，因此默认拒绝。
- 完全退出程序、启动器、更新器和辅助进程；迁移过程中每隔数秒重新检查。
- 外接盘应保持稳定挂载路径。断开时立即停止，不得在同名的内置目录中继续写入。
- 断开外接盘前完全退出程序。大版本更新后重新验证签名、链接/位置设置和真实读写。

## 成功门槛

以下条件缺一不可：

1. 源仍存在时，完整树、每个普通文件 SHA-256、元数据、ACL、扩展属性、软链接与硬链接校验通过。
2. `.app` 通过严格深层签名校验。
3. 外接副本真实启动，读取已有内容并完成安全写入。
4. 完全退出后再次启动成功，新写入确认位于外接盘。
5. 更新器、登录项或辅助进程的行为已检查，且没有新的沙盒拒绝。

未达到全部条件时，不能引导用户删除内置源程序或源数据。
