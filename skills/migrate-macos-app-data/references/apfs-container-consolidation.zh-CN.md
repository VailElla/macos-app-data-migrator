# 外接 APFS 容器整合

本流程用于把同一块外接 GPT 磁盘上相邻 APFS 容器的数据，经磁盘末尾的临时 APFS 分区完整暂存和校验后，合并到保留容器。它是低自由度的人工操作流程，不是 `migrate_app_data.py` 的新破坏性子命令。

## 硬边界

- 只处理已经证明为外接、GPT、APFS 的物理磁盘；系统盘、Fusion Drive、RAID、加密状态不明或拓扑不明时停止。
- 临时分区与源数据位于同一物理磁盘，因此只是迁移暂存区，不是备份。重要数据仍应有另一块物理介质上的独立备份。
- `diskutil` 的 `diskN`、`diskNsM` 会在断开、USB 重置或重新枚举后改变。每个删除、调整大小或改名动作前，都按容器 UUID、宗卷 UUID 和物理存储 UUID 重新解析当前标识。
- 删除容器不可逆。只有完整校验通过、剩余差异已经逐项披露并由用户明确接受后，才可删除当时正在充当源的容器。
- `com.apple.provenance` 不是通用忽略项。普通数据仍严格比较；若只有受系统保护、无法恢复的 provenance 差异，报告准确路径和数量，取得用户明确接受后才能越过删除门。
- 不把整块宗卷根目录交给 `migrate_app_data.py`。它有意只接受一个 `.app` 或一个范围明确的数据目录。整盘整合按顶层组件逐个迁移和校验，根目录普通文件另行逐项处理。

## 0. 只读锁定拓扑

先退出会写入两个宗卷的程序、启动器、同步器和索引任务。保存下列证据：

```bash
diskutil list
diskutil apfs list
diskutil info -plist "/Volumes/Source"
diskutil info -plist "/Volumes/Destination"
diskutil apfs resizeContainer <destination-container-current-id> limits
lsof +D "/Volumes/Source"
```

记录物理磁盘是否为外接、分区起点和顺序、容器/宗卷/物理存储 UUID、挂载点、容量、已用空间、可扩容上限和快照。临时分区容量必须大于源负载、元数据开销和安全余量；APFS 的“已用空间”不能代替实际顶层路径清单。

建立一张动作清单：本轮保留哪个容器、暂存哪个容器、删除哪个容器、每次动作期望释放哪一段连续空间。任何相邻关系不明确都停止。

## 1. 建立临时 APFS 分区并暂存

仅在已经确认位于物理磁盘末尾的空闲空间中建立临时 APFS 分区。执行分区表写入前，再次检查整盘标识和物理磁盘 UUID；不要把示例占位符直接粘贴执行。

逐个顶层组件运行 `audit`、`copy --execute` 和 `verify`。保持源静止，日志与 partial 全部写在临时宗卷。宗卷根目录的普通文件逐个复制并计算 SHA-256；先分类再排除 `.Spotlight-V100`、`.fseventsd`、`.TemporaryItems`、`.Trashes`、安装暂存区等系统生成内容。

即使目录复制工具报告成功，也必须比较完整的相对路径集合。`ditto` 会把某些以 `._` 开头的普通文件当作 AppleDouble 旁车而漏掉；对差集中的每个路径确认类型，再用精确源路径补复制并校验哈希，不能按前缀一概忽略。

跨宗卷复制后，恢复源端存在的所有非 provenance 扩展属性，并按由深到浅的顺序重放目录权限、ACL、时间戳和扩展属性。随后再次执行完整树校验。

## 2. USB 重置时安全停止

出现 `Device not configured`、宗卷消失、I/O 错误或设备号变化时立即停止写入：

1. 重新运行 `diskutil list`、`diskutil apfs list` 和 `diskutil info -plist`，用记录的 UUID 解析新的动态标识。
2. 对未挂载或只读状态下适合检查的容器运行 `fsck_apfs -n`，并重新读取、重新哈希失败文件。
3. 重新检查所有挂载点和目标保护条件。
4. 旧日志若绑定的 `st_dev`、inode、挂载点或宗卷身份已改变，就从当前可信快照重新开始；不要编辑日志绕过身份检查，也不要继续使用旧 `diskN`。

## 3. 删除旧容器并扩大保留容器

在删除动作前的最后一刻，重新解析并逐项显示：

- 物理磁盘 UUID 与外接状态；
- 待删除容器 UUID、其中宗卷 UUID 和挂载点；
- 保留容器 UUID及其相邻空闲区；
- 临时容器 UUID、完整校验状态和当前可读性；
- `lsof` 中是否仍有写入者。

只有用户明确授权该准确 UUID 后，才可执行等价于：

```bash
diskutil apfs deleteContainer <verified-old-container-current-id>
diskutil apfs resizeContainer <verified-destination-container-current-id> 0
```

第一次扩容只会到临时分区边界。命令完成后立即重新枚举，不假设标识保持不变。

## 4. 合并回保留宗卷

复制前生成源与目标的相对路径、条目类型和普通文件 SHA-256 清单：

- 同路径同类型同内容：保留并校验。
- 同路径但类型或内容不同：先把目标版本复制到目标宗卷中的冲突归档，校验归档，再按已批准的“暂存源优先”规则写入最终路径。
- 只在目标存在：只有列入目标保留清单才保留。
- 只在暂存源存在：复制到最终路径。

不要用“文件数差不多”代替路径集合比较。完成合并后再次补齐 `._` 普通文件、恢复非 provenance xattr、由深到浅恢复目录元数据，并以暂存源为基准执行完整哈希和元数据校验。冲突归档在用户完成最终测试前保留。

## 5. 改名并修复引用

改名只改变宗卷显示名，不会自动修复绝对路径。把保留宗卷改为最终名称后，重新枚举并修复所有功能性引用：

- `/Volumes/旧名/...` 软链接；
- 启动器、脚本、项目配置和环境变量；
- 应用原生存储位置、安全作用域书签和最近打开项目；
- 登录项、自动化和更新器配置。

重新构建指向最终路径的新启动器，不覆盖旧启动器。旧启动器可能仍包含旧绝对路径；测试通过后只通过访达移到废纸篓。

## 6. 最终删除门

在删除临时容器前必须全部满足：

- 暂存来源路径的完整哈希、类型、ACL、xattr、软链接和硬链接校验已通过；任何 provenance 例外有准确清单和用户明确接受。
- 最终宗卷完成真实读写、项目打开保存、应用完全退出重启和更新器检查；用户已确认关键程序正常。已经由用户完成并确认的测试无需重复。
- 新写入确实落在最终宗卷，旧绝对路径没有仍在使用的功能性引用。
- 最终宗卷与临时宗卷均通过适当的只读文件系统检查，且没有活动写入者。

然后再次按 UUID 解析临时容器，取得用户对该准确容器的删除授权，删除临时容器并把保留容器扩大到磁盘末尾。最终保存 `diskutil list`、`diskutil apfs list`、`df`、文件系统检查和校验摘要。

删除旧源容器前可以停止并保留原布局；删除旧源后、删除临时容器前，临时宗卷是恢复源；临时容器删除后，本流程不再提供同盘回滚。
